# 04 — Database (Supabase / Postgres)

## Migration deliverables (read first)

The owner applies migrations himself. Produce:

1. **`supabase/migrations/`**: one file per logical step, named `YYYYMMDDHHMMSS_short_name.sql`, in dependency order, for example:
   - `..._extensions.sql` (pg_trgm, unaccent, pgcrypto, pg_cron, pg_net if used)
   - `..._enums_and_helpers.sql`
   - `..._profiles_and_auth.sql`
   - `..._taxonomy.sql` (categories, tags, formats)
   - `..._media.sql`
   - `..._articles.sql`
   - `..._pages_menus_homepage.sql`
   - `..._settings.sql`
   - `..._ads.sql`
   - `..._analytics.sql`
   - `..._search.sql`
   - `..._rls_policies.sql`
   - `..._storage.sql` (bucket + storage policies)
   - `..._cron_jobs.sql`
2. **Idempotency where cheap**: `create extension if not exists`, `create table if not exists` is not required, but every migration must run cleanly once on a fresh project in order.
3. **`supabase/ALL_MIGRATIONS.sql`**: all migrations concatenated in order, with a header comment per file, generated by `scripts/build-all-migrations.ts` (`pnpm db:bundle`). The owner can paste this into the Supabase SQL editor in one go.
4. **`supabase/seed.sql`**: required base data (settings, categories, formats, homepage sections, ad slots, menus, static page stubs). Safe to run once after migrations.
5. **`supabase/demo-seed.sql`** and **`supabase/demo-clear.sql`**: demo content flagged with `is_demo = true`, removable.
6. **`supabase/bootstrap_admin.sql`**: `update profiles set role = 'admin' where id = (select id from auth.users where email = '<EMAIL>');` with clear instructions.
7. **`supabase/APPLY.md`**: step-by-step, for a non-expert, in English with Arabic headings optional:
   - create the project (region closest to Tunisia, e.g. an EU region),
   - Auth settings (disable sign-ups, site URL, redirect URLs),
   - run `ALL_MIGRATIONS.sql` in the SQL editor (or `supabase db push` with the CLI),
   - run `seed.sql`, optionally `demo-seed.sql`,
   - create the first user and run `bootstrap_admin.sql`,
   - where to find the keys and which env var each goes into,
   - how to verify (a checklist of queries).
8. Also test the whole sequence locally with the Supabase CLI (`supabase start`, `supabase db reset`) and record the result in `PROGRESS.md`.

Never edit an applied migration later; add a new one.

## Conventions

- Primary keys: `uuid` default `gen_random_uuid()`, except where noted.
- Timestamps: `timestamptz`, `created_at default now()`, `updated_at` maintained by a shared trigger `set_updated_at()`.
- Bilingual labels: `name_ar`, `name_fr` (French nullable; fall back to Arabic when empty).
- Slugs: lowercase ASCII `[a-z0-9-]`, unique per table, used in URLs for categories/tags/authors/pages. Articles use a numeric `public_id` in URLs (see articles).
- `is_demo boolean not null default false` on content tables (articles, media, profiles of demo authors, tags created by demo) so demo data can be removed.
- Soft delete is not needed except for articles (`status = 'archived'`) and users (`is_active = false`).

## Helper functions

- `set_updated_at()` trigger function.
- `current_role_name() returns app_role` — `security definer`, `stable`, returns the role of `auth.uid()` from `profiles` where `is_active`; null if none.
- `is_staff()`, `is_editor_or_admin()`, `is_admin()` — boolean wrappers used in policies.
- `normalize_ar(text) returns text` — `immutable`. Lowercase, `unaccent`, strip Arabic diacritics (tashkeel U+064B–U+0652, tatweel U+0640), unify alef forms (أ إ آ ٱ → ا), ة → ه, ى → ي, ؤ → و, ئ → ي. Used for search. Unit-test it in SQL (a few `select` assertions in a test file).
- `estimate_reading_minutes(text)` — words / 200 (Arabic) rounded up, min 1.

## Search

- `articles.search_vector` = `setweight(to_tsvector('simple', normalize_ar(title)), 'A') || setweight(to_tsvector('simple', normalize_ar(coalesce(subtitle,''))), 'B') || setweight(to_tsvector('simple', normalize_ar(coalesce(body_text,''))), 'C')`. Use a trigger (not a generated column) if `normalize_ar` can't be marked immutable because of `unaccent`; wrap `unaccent` in an immutable SQL function with an explicit dictionary as usual.
- RPC `search_articles(q text, lang content_language default null, limit int, offset int)` — `security invoker`, returns published articles ranked by `ts_rank` with a trigram fallback on title for short or misspelled queries.
- French content also goes through `simple` + unaccent. That's fine for v1.

Implementation notes:
- Authors' status restrictions are enforced with a `before update` trigger (RLS alone can't compare old/new cleanly): if `current_role_name() = 'author'`, reject transitions to `published`/`scheduled`/`archived` and changes to `published_at`, `is_featured`, `is_breaking`, `is_sponsored`.
- **No role, including admin, gets `insert/update/delete` on analytics raw/rollup tables or `ad_daily_stats`.** Only the service role (server) and the cron functions (`security definer`) write them. This is the "stats can't be faked" guarantee; mention it on the media kit page.
- Stats access for authors goes through RPCs (`my_article_stats(from, to)`, `my_summary(from, to)`) that filter by `article_authors.profile_id = auth.uid()`.

## Storage

- Bucket `media`: public read. Insert/update/delete allowed for staff (`is_staff()`); authors can delete only objects they uploaded (check `owner`).
- Max upload size 10 MB enforced by bucket config; images only (`image/jpeg, image/png, image/webp, image/avif`).
- Path convention: `YYYY/MM/<uuid>/original.webp`, `.../w480.webp`, etc.

## Cron jobs (`pg_cron`)

| Job | Schedule | What |
|---|---|---|
| `publish_scheduled` | every minute | `update articles set status='published', published_at = scheduled_for, first_published_at = coalesce(first_published_at, scheduled_for) where status='scheduled' and scheduled_for <= now()` |
| `expire_breaking` | every 5 min | `is_breaking=false` where `breaking_until < now()` |
| `rollup_hourly` | every hour at :05 | roll up today and yesterday (idempotent upsert) |
| `rollup_nightly` | daily 02:15 Africa/Tunis (convert to UTC in the schedule) | full rollup of yesterday, monthly uniques for current month, prune raw rows older than `raw_retention_days`, prune revisions beyond 30 per article, record in `rollup_runs` |
| `rotate_salt` | 1st of month 00:05 | create next month's salt; delete salts older than 2 months |

All job functions are `security definer` with `search_path` set explicitly.
